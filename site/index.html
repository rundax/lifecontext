Self-hosted · source-available · v1.2

Your documents, compiled. Every claim cited.

Give Claude Code, Codex and your other agents your contracts, letters, scans and notes. LifeContext keeps the files on your machine, sends their text only to the model you choose, and cites every claim with the exact quote, its page or passage, and the source version, so you can check it.

For people who work with AI agents and keep documents that matter: leases, contracts, insurance, tax and medical letters, research PDFs, scans in English, Ukrainian or Russian.

Install View on GitHub
  • Free for one person for their own use, including at work; businesses need a commercial licence
  • Linux, and macOS on Apple silicon
  • One install command and an API key

[2]How it works

From original file to cited page

Everything runs on your machine. Apart from the one-time model download, requests leave it for two destinations: the model provider you choose, and a vision model if you turn one on.

  1. Originals

    Every file you add is stored unchanged: checksummed, immutable and versioned. A correction adds a new version; nothing is overwritten.

  2. Extraction and OCR

    Text comes out of TXT, Markdown, PDF (book-length too), DOCX, XLSX, PPTX and images. Scans go through local Tesseract OCR for English, Ukrainian and Russian.

    A vision model you configure can read handwriting, photos and charts. It is off by default.

  3. Index

    Built on the open-source Hindsight memory engine. LifeContext configures a multilingual reranker for English, Ukrainian and Russian text.

  4. Compiled wiki

    Each document gets its own page. Shared topic and entity pages collect claims from several documents and link to each other.

    • Every claim is a literal quote, checked against the source text before the page is written, with a citation to source, version and passage.
    • A short summary above the quotes is labelled as model-written.
    • Contradictions the model finds are recorded and never auto-resolved.
    • Correcting or forgetting a source marks the pages that depend on it as stale.

  5. Obsidian and your agents

    Pages are written as Markdown into your Obsidian vault. Each page has a section for your own notes, kept byte for byte. If you edit the generated part, LifeContext reports a conflict instead of overwriting it.

    Your agents read the same pages and evidence through one skill or the MCP server.

Keeping it current

  • Daily brief and change logWhat was imported, which pages changed, new contradictions and pages that went stale.
  • wiki lintReports stale pages, open contradictions, orphan pages and gaps. It reports; it changes nothing.
  • JournalWrite notes in Obsidian or through an agent. Entries are named by date and title, indexed and searchable; compiling the journal into wiki pages comes in v1.3.
  • Export and importMove a library between machines as a bundle.
  • Backup and restoreBack up originals, catalog, index and vault, and restore them into a fresh home directory.
  • Bring your own modelAnthropic, OpenAI, Google Gemini, OpenRouter or any OpenAI-compatible endpoint, local ones included. You choose; there is no default.

[3]Install

Install

One command on Linux and macOS, a container image for everything else, or a plain checkout if you want to read the code first. Every way asks you to choose the model; there is no default.

install.sh

1 · Install

Terminal
curl -fsSL https://github.com/rundax/lifecontext/releases/latest/download/install.sh | sh

It asks which model to use (Anthropic, OpenAI, Google Gemini, OpenRouter, a local model server or another OpenAI-compatible endpoint; there is no default), checks that the model answers, starts LifeContext as a user service and gives your agents the skill.

2 · Open the vault in Obsidian

Choose “Open folder as vault” and pick ~/LifeContext/vault, or the folder you gave the installer. Any Markdown editor works too.

3 · Import a document and ask your agent

Terminal
lifecontext documents import ~/Documents/lease.pdf

Indexing and compiling call your model and can take a few minutes; the page then appears under Journal/wiki/ in the vault. Ask Claude Code, Codex or Gemini CLI: “What does my lease say about the deposit?” The agent answers from LifeContext’s evidence: the quote, the page and the version of the lease it came from.

Docker

The image includes Tesseract with English, Ukrainian and Russian and the local models, and runs as an unprivileged user. No port is published: the service listens on loopback inside the container, and you talk to it with docker exec. Your key goes in a Compose secret, never into the image; the other settings apply on the first start. Set the provider and model you chose: there is no default, and without them the container waits and logs which one is missing.

compose.yaml

compose.yaml
services:
  lifecontext:
    image: ghcr.io/rundax/lifecontext:1.2.0
    container_name: lifecontext
    restart: unless-stopped
    environment:                      # used on the first start only
      LIFECONTEXT_PROVIDER: anthropic
      LIFECONTEXT_MODEL: claude-sonnet-5
    secrets: [lifecontext_api_key]    # the key, readable by uid 1000
    volumes:
      - home:/data/home               # settings, index, backups
      - vault:/data/vault             # your Obsidian vault

secrets:
  lifecontext_api_key:
    file: ./secrets/lifecontext_api_key

volumes:
  home:
  vault:

Add the key, start, check

Terminal
mkdir -p secrets
(umask 077 && cat > secrets/lifecontext_api_key)   # paste the key, Enter, Ctrl-D
docker compose up -d
docker compose exec lifecontext lifecontext doctor

Agents on the host reach the container through the lifecontext-docker wrapper. The full compose.yaml, with the health check and limits, is in the repository.

Without Compose

Terminal
docker run -d --name lifecontext \
  -e LIFECONTEXT_PROVIDER=anthropic -e LIFECONTEXT_MODEL=claude-sonnet-5 \
  -v "$PWD/secrets/lifecontext_api_key:/run/secrets/lifecontext_api_key:ro" \
  -v lifecontext-home:/data/home -v lifecontext-vault:/data/vault \
  ghcr.io/rundax/lifecontext:1.2.0

On Linux, the key file must be readable by uid 1000 in the container (sudo chown 1000 it).

From source

Needs Python 3.12, uv, and Tesseract with the eng, ukr and rus language data. On Linux the constraints file keeps PyTorch on its CPU build; on macOS run uv pip install -e . instead.

Terminal
git clone https://github.com/rundax/lifecontext.git
cd lifecontext
uv venv --python 3.12 && . .venv/bin/activate
uv pip install -c constraints-cpu.txt -e . \
  --extra-index-url https://download.pytorch.org/whl/cpu \
  --index-strategy unsafe-best-match   # Linux, CPU-only PyTorch
lifecontext init                         # provider, model, API key, vault folder
lifecontext preflight --model-probe      # one short call to check the model
lifecontext service install --maintenance
lifecontext skills install               # Claude Code, Codex, Gemini CLI, Hermes
lifecontext doctor

Requirements

  • Linux (x86_64 or aarch64, glibc 2.35 or later) or macOS 14 or later on Apple silicon, natively.
  • Windows through Docker or WSL.
  • An API key from the model provider you choose (Anthropic, OpenAI, Google Gemini or OpenRouter), or a local model server such as Ollama, vLLM or LM Studio.
  • About 3 GB of disk for the runtime and models (measured in CI on Linux: 2.4 GB for the installation, 0.6 GB for the models). The installer downloads the embedding and rerank models once.
  • Recall reranks on the CPU; expect tens of seconds on a 4-core machine.

What the installer does

  • Checks your operating system and CPU, and stops with a clear message on combinations it does not support.
  • Downloads the release over HTTPS, checks its SHA-256 checksums and, with cosign 3 or later, their signature, and installs every dependency from a lock with pinned hashes.
  • Installs into your home directory. Running LifeContext never needs root.
  • Installs Tesseract with English, Ukrainian and Russian through Homebrew on macOS, or through apt, dnf or pacman when sudo works without a password. It never asks for a password; otherwise it prints the command to run.
  • Asks which model to use, with no default, and checks with one short request that it answers. Your API key is read with a hidden prompt, never passed on the command line.
  • Runs init, service install --maintenance, skills install and doctor, and ends with three next steps.
  • Run it again to upgrade: it stops the service, backs up your data, installs, and starts the service again.
  • Leaves vision off.

Read the script before piping it to sh: it is in the latest release.

Works with your agents

One skill for command-line agents and one MCP server for MCP clients. Both talk to the same local service and read the same cited pages.

Agent skill lifecontext skills install

One copy of the skill, linked into each agent it finds. Agents capture journal text, import documents, recall with evidence and read wiki pages through the lifecontext CLI.

MCP server lifecontext mcp

New in 1.2. A local stdio server for MCP clients such as Claude Desktop and Cursor. It is read-only by default; add --allow-writes to the arguments to let clients capture and import.

JSON
{
  "mcpServers": {
    "lifecontext": {
      "command": "/home/you/.local/bin/lifecontext",
      "args": ["mcp"]
    }
  }
}

For command, use the output of command -v lifecontext; desktop apps do not read your shell PATH.

Bring your own model

LifeContext uses one model at a time. There is no default: the installer and init ask you to choose one of these.

  • Anthropic
  • OpenAI
  • Google Gemini
  • OpenRouter
  • A local model server (Ollama, vLLM, LM Studio)
  • Another OpenAI-compatible endpoint

What agents are allowed to do. A connected agent runs the CLI with your authority. The skill tells it what not to do (no repairs, no edits to internal state, report failures instead of retrying around them); LifeContext does not enforce separate permissions per agent.

What we found no one else documenting

Among the products above, we found no other product that documents:

  • a mechanical check that each quoted claim appears word for word in the cited source passage before a page is written;
  • citations pinned to a specific version of a source in a versioned store;
  • built-in local OCR that names Ukrainian and Russian.

Where others go further

  • Hosted versions you can use without installing anything, for example Gemini Notebook and Claude. LifeContext is self-hosted only.
  • Their own reading interface or graph view. LifeContext uses Obsidian for reading.
  • Audio, video and web capture. LifeContext reads documents and images.
  • Team sharing. LifeContext is built for one person.
  • OSI-approved licences: most of the self-hosted projects above are MIT, Apache-2.0, AGPL-3.0 or GPL-3.0.

[6]Privacy

What leaves your machine

Runs on your machine. Originals never leave it. Extracted text goes to the model provider you choose; with a local model it stays on your machine (supported, not yet part of release qualification). Page images go to a vision model only if you turn one on.

Stored on your machine

  • Original files and every version of them; these never leave it
  • Extracted text and OCR output
  • The index, the compiled pages and your vault
  • Your API key, in a private .env file

Goes to your model provider

All extracted text and journal entries, in chunks, when they are indexed, and passages again when pages are compiled, with the prompts for both. You pick the provider; with a local model nothing goes out.

Goes to a vision model

Page images, and only if you configure a vision model. Vision is off by default.

Downloaded once

The first start downloads the embedding and rerank models. This website loads nothing from other sites and uses no analytics or cookies.

What we do not claim

No compliance certifications
LifeContext has not been audited or certified against GDPR, HIPAA, SOC 2 or any other standard.
Not “no hallucinations”
The quote check proves the quoted text exists in the text LifeContext extracted from the source. It does not prove that OCR or a vision model read the original correctly (model-read text is labelled), that a summary is right, that the best quotes were chosen, or that the source is correct.
Not every contradiction is found
The model proposes them while compiling; LifeContext records them but can miss some.
No per-agent permissions
Agents act with your authority. The skill sets out what they must not do; the application does not enforce it.
No benchmark numbers
We have not run a comparable test against other products, so we publish no accuracy or speed comparisons.

Which licence is it, and what can I do with the code?

BUSL-1.1. The code is public, and reading, evaluating and testing it is free for everyone. BUSL-1.1 is not an OSI-approved licence, so we describe LifeContext as source-available. Each release becomes Apache-2.0 on or before its Change Date (2030-11-08 for 1.2.0).

Can I use it at work, with my employer’s documents?

Yes, if you run your own copy for your own use. That includes documents that belong to your employer or your clients. A commercial licence is needed when your employer installs, provides or manages LifeContext for its staff.

I work as a freelancer or sole proprietor. Is client work free?

General

Why not just RAG?

Retrieval finds passages when you ask, and the answer is assembled again every time. LifeContext retrieves too (that is the Hindsight index), and it also compiles: it writes pages you can read, correct and link, keeps them current as sources change, and records where sources disagree.

Your agents get both: recall with evidence for a question, and pages for what you already know.

What does it cost per document?

Running your own copy is free. The cost is your model provider’s token price: indexing and compiling a document takes several model requests, so a long book costs more than a one-page letter, and a cheaper model costs less. OCR runs locally and costs nothing.

We do not publish a per-document figure because it depends so much on the model and the document. With a local model there is no per-token cost at all.

Does it work offline?

Storage, OCR, the index, the reranker and the Obsidian projection all run locally. Indexing and compiling need the model provider; with a cloud provider that means a connection. With a local model through Ollama or vLLM, LifeContext can run without one once the first start has downloaded the embedding and rerank models. Local-model operation is supported but not yet part of release qualification.

Which languages does it handle?

OCR covers English, Ukrainian and Russian. LifeContext configures a multilingual reranker for English, Ukrainian and Russian text. Quotes stay in the language of the source, because they are literal.

Is my data used for training?

There is no LifeContext cloud, so your data never reaches us. Whether your model provider may use API traffic for training depends on that provider’s terms; check them, or use a local model.

How is this different from Karpathy’s LLM Wiki pattern?

LifeContext is inspired by the LLM Wiki pattern: raw sources, a wiki maintained by a model, and a lint pass. It adds custody (immutable, checksummed, versioned originals), literal quotes checked against the source before a page is written, contradictions that stay open until you decide, and stale markers when a source is corrected or forgotten.

Do I need Obsidian?

No. The vault is a folder of Markdown files that any editor can open. Links, page names and the graph view are designed with Obsidian in mind.

Are my notes compiled too?

In v1.2, journal entries and notes you put in Journal/Inbox are indexed and searchable next to your documents, and your agents can recall them with citations. Compiling the journal into wiki pages comes in v1.3. A Markdown file you import as a document is compiled like any other document.

Can I use it on my phone or on several devices?

Advanced and optional. LifeContext runs on one machine, and the vault is a folder there. To read and write the vault on a phone or a second computer, the Self-hosted LiveSync plugin for Obsidian can sync it through a hub on that machine, reached over Tailscale. It takes Docker, Tailscale and some setup on every device; the sync guide walks through it.

Who is it not for?

People who want an app with no computer to run it on: LifeContext runs on your own Linux machine or Mac, or in Docker. Teams that want one shared knowledge base: it is built for one person. Anyone looking for audio, video or web capture: it reads documents and images.
